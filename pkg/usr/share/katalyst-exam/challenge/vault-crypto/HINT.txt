Hint: look closely at the function called _derive_seed() in encrypt.py.

It runs the key through SHA-256, which normally gives an enormous
number of possible results -- way too many to ever guess by trying
each one. But look carefully at how much of that result actually gets
used as the starting number for generating the keystream. Is it really
using all of it, or only a small piece?

Once you figure out how many different starting numbers are actually
possible, writing a script to try every single one becomes fast and
realistic.

There's no obvious marker (like "the answer is...") in the decrypted
message. You'll need to write code that checks whether a decrypted
result looks like real, readable English text -- as opposed to random
garbage -- to automatically recognize when you've found the right one.
